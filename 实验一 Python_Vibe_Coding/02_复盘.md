# 复盘：哪些交给 AI、哪些自己拍板、哪些风险人工审查

## 一句话总结

这次我把「写代码的体力活」全部交给 AI，把「定义正确」牢牢留在自己手里：先用一份写死验收数值的澄清清单框住 AI 的自由度，再让它按小步产出、每步立刻跑一遍；最后靠 Code Review 抓出一个 AI 没意识到的数据一致性漏洞（单价 ≤ 0），并只做最小修改。**跑通不等于交付，可核对、可复现、可解释才算交付。**

## 1. 交给 AI 的环节

- **样板与重复劳动**：pandas 读写 Excel、openpyxl 版式、FastAPI 路由与 Pydantic 模型、SQLite CRUD、pytest 参数化用例、命令行参数解析——这些语法性、模板性工作由 AI 一次成型，省下大量查文档时间。
- **样例数据构造**：按我给的口径生成 16 行含空值 / 重复 / 负数量 / 零数量 / 非法日期的原始数据。
- **证据与文档初稿**：运行日志渲染成截图的脚本、README 目录说明、过程记录表格的初稿。
- **环境排障的执行部分**：切 pip 源、补依赖、改代理绕行，都是描述清楚问题后让 AI 落地最小修改。

## 2. 自己拍板的环节（不交给 AI 判断）

| 决策 | 为什么不交给 AI |
|---|---|
| 交付物形态：桌面 `python/` 下**唯一一个**总文件夹，内分 `src / tests / data / evidence / tools` | 这是人对「交什么、怎么交」的责任，AI 容易散落文件或塞满根目录 |
| 「月度总额」按月分组、日期严格 `YYYY-MM-DD`、类型枚举用中文、错误码用 422 | 题目有歧义，必须由人定死并写进 prompt，否则 AI 会选一个看似合理但不可核对的解释 |
| 统计口径单一：四个工作表全部从**同一份清洗结果**派生 | 防止 AI 分别算导致「按销售员合计 ≠ 按地区合计」 |
| 人工核对基准 23700 / 14400 / 15300 / 19600… | 数值先验由人独立算出来，AI 只能被验证，不能自己定验收线 |
| 并发方案：SQLite + `BEGIN IMMEDIATE` + 写锁 + AUTOINCREMENT，而非内存 list | 涉及数据一致性，架构选择由人负责 |
| 补充「单价 ≤ 0 也剔除」 | 属于扩大题目规则，是业务判断，不能让 AI 自己加 |
| 截图用真实日志渲染 + 保留原始 `.txt`、`README` 明示「非录屏」 | 诚信边界：证据可以美化呈现，不能伪造来源 |

## 3. 人工审查过的风险

- **数据一致性**：用 sha256 断言原始文件前后不变；清洗顺序固定；剔除行数分步骤记录进「总览」，任何静默丢数都能被发现。
- **异常输入**：缺列、空文件、只有表头、全脏数据、文件不存在，逐一手验「可读提示 + 退出码 2 + 不产出半成品」，并专门检查 CLI 不吐栈回溯。
- **并发**：不满足于「能说明」，直接写 16 线程 × 40 次真实 POST 的用例，断言 id 唯一、条数、金额三者同时正确。
- **安全**：SQL 全部参数化；无 `eval`、无路径拼接执行；接口输入经 Pydantic 严格校验；错误体不回传内部异常栈。
- **性能 / 资源**：每请求独立连接、WAL、单条 SQL 聚合；共享内存库用常驻连接防止提前销毁；uvicorn 子进程在 `finally` 中确保回收。
- **环境可复现**：`requirements.txt`、`pytest.ini`、一键脚本、端口与代理处置全部显式写死，换台机器也能跑。
- **数值精度**：确认 float 的局限，汇总处 `round(2)`，并在 README「已知限制」里如实写明生产环境应改整数分——**没有把已知缺陷藏起来**。

## 4. 做得不够的地方 / 下次改进

1. **过程记录仍依赖会话**：完整 AI 对话留在 WorkBuddy 会话里，本目录只有关键摘要；下次应从第一步起就把每轮 prompt 与回执落盘成 `chat_log.md`，不依赖平台留存。
2. **验证偏「后置集中」**：虽然分了 S0–S6，但 Code Review 的 R1 是在写完测试后才发现的「口径漏洞」；更理想的做法是在澄清清单里就把「单价 ≤ 0」这类衍生脏数据一并枚举，让 AI 一次写对。
3. **没有真正的录屏**：交付的是日志渲染截图。若评分严格要求录屏，应在一键运行时同步录制终端。
4. **依赖版本未锁定**：`requirements.txt` 用的是下限版本，本机 pandas 3.1.1 / fastapi 0.162.2 通过；更稳妥应输出 `pip freeze` 的精确版本便于复现。
5. **接口缺少鉴权与幂等**：作为练习题可接受，但若演进成真实服务，需要补 token、幂等键与金额整数化，这些已在「已知限制」标注，没有 pretending 它是生产可用。
