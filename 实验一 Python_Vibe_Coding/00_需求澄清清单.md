## 0. 全局目标与约束

| 项 | 约定 |
|---|---|
| 目标 | 用自然语言驱动 AI 完成两个可运行的 Python 工程任务，并留下可验证的过程证据 |
| 运行环境 | Python 3.10+（本机实测 3.13.14）；允许 pandas / openpyxl / fastapi / uvicorn / pytest |
| 运行方式 | 在作业根目录一键运行 `python run_all.py`（Windows 也可双击 `run_all.bat`） |
| 目录 | 所有交付物收进单一根目录 `Python_Vibe_Coding_lab1/`，`src` / `tests` / `data` / `evidence` / `tools` 分层 |
| 非目标 | 不做前端页面、不做用户体系、不联网、不改原始输入文件、不引入题目允许范围外的框架 |

**待确认点 → 本人拍板的默认决策**（写进 prompt 前先定死，避免 AI 自由发挥）：

1. 「月度总额」按 `日期` 解析出 `YYYY-MM` 分组，总览工作表逐月列出并给出合计；样例数据刻意跨 10/11 两个月。
2. 日期格式为 `YYYY-MM-DD` 严格 10 位，且必须是真实存在的日期。
3. 接口字段用题目原文的中文名（金额 / 类型 / 分类 / 日期），类型枚举为 `收入` / `支出`。
4. 非法参数统一返回 4xx + `{"error": {"code", "message", "details"}}`。
5. 存储默认用 SQLite 共享内存库（一键运行不留文件），可用 `LEDGER_DB` 环境变量切到文件持久化。

## 1. 考题一：Excel 报表生成脚本（必做，40 分）

**输入**：`data/sales_raw.xlsx`，字段固定为 `日期、销售员、产品、数量、单价、地区`；含空值、重复行、负数量、零数量、非法日期等脏数据。

**输出**：`data/report.xlsx`，恰好四个工作表：`明细清洗后`、`按销售员`、`按地区`、`总览`。

**处理规则（顺序不可颠倒）**

1. 删除关键字段缺失 / 非法的行（文本空串、数值无法转换均算缺失）；
2. 剔除 `数量 <= 0` 的异常行；
3. 按全部 6 个字段去重（保留首次出现）；
4. 计算 `销售额 = 数量 × 单价`；按销售员、按地区汇总销售额；按 `YYYY-MM` 汇总月度总额；
5. 输出四个工作表，表头加粗、冻结首行、列宽自适应。

**边界与异常（必须给可读提示，不崩溃、不产出半成品）**

| 场景 | 期望 |
|---|---|
| 输入文件不存在 / 是文件夹 | 明确报错，退出码 2 |
| 0 字节空文件 | 明确报错「为空」 |
| 只有表头、无数据行 | 明确报错「没有数据行」 |
| 缺必需字段 | 报错并列出缺哪些字段 |
| 清洗后无有效数据 | 明确报错「没有任何有效数据行」 |
| 任何其他情况 | 原始文件 sha256 前后一致（绝不写回） |

**验收标准（人工核对基准值，写死在 pytest 里）**

| 维度 | 核对值 |
|---|---|
| 有效行数 | 8（原始 16 行，剔除 8 行） |
| 明细销售额逐行 | 10000 / 400 / 3600 / 600 / 5000 / 2400 / 800 / 900 |
| 按销售员 | 张三 14400、李四 5400、王五 3000、赵六 900 |
| 按地区 | 华东 15300、华北 5400、华南 3000 |
| 月度总额 | 2026-10 = 19600，2026-11 = 4100，合计 **23700** |
| 恒等式 | 按销售员合计 = 按地区合计 = 月度合计 = 23700 |

## 2. 考题二：FastAPI 记账接口

**存储**：SQLite；默认共享内存库，可切文件持久化。

| 接口 | 输入 | 输出 / 校验 |
|---|---|---|
| `POST /records` | 金额、类型[收入/支出]、分类、日期 | 金额 > 0、类型合法、分类非空、日期 `YYYY-MM-DD` 且真实；成功 201 返回带 id 的记录 |
| `GET /records` | 类型、分类、开始日期、结束日期、page≥1、1≤page_size≤100 | 按条件筛选并分页，返回 `{total, page, page_size, items}` |
| `GET /summary` | 开始日期、结束日期（可选） | 返回收入合计、支出合计、结余 |
| 任意非法参数 | — | 4xx + 统一结构化错误体 |

**并发写入要求**：40 个并发 POST 后，id 不重复、条数 = 40、金额合计 = 40；需能说明保证机制。

**验收标准**：uvicorn 可真实启动并可调用（不止进程内测试）；校验用例返回预期状态码；pytest 覆盖核心用例；并发写入结果一致。
